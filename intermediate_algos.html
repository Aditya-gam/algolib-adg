Intermediate Algorithms¶

This guide covers intermediate-level algorithms that build upon basic data structures to solve common computational problems.

Overview¶

Intermediate algorithms introduce more sophisticated problem-solving techniques including divide-and-conquer, greedy strategies, and graph traversal methods.

Sorting Algorithms¶

Sorting is one of the most fundamental algorithmic problems. Different sorting algorithms offer various trade-offs between time complexity, space complexity, and stability.

Bubble Sort¶

A simple comparison-based sorting algorithm that repeatedly steps through the list, compares adjacent elements, and swaps them if they are in the wrong order.

Bubble sort algorithm implementation.

class algolib.algorithms.sorting.bubble.BubbleSorter(*args, **kwargs)

Bases: Sorter[ComparableT]

Bubble sort implementation.

This is a simple, stable sorting algorithm that repeatedly steps through the list, compares adjacent elements and swaps them if they are in the wrong order. The pass through the list is repeated until the list is sorted.

sort(data: MutableSequence[ComparableT]) → MutableSequence[ComparableT]

Sorts a mutable sequence using the bubble sort algorithm.

This implementation includes an optimization to exit early if the list becomes sorted before all passes are complete. It creates a new list to avoid modifying the original data.

Parameters:

data – The sequence to sort.

Returns:

A new list containing the sorted elements.

Time Complexity: O(n²) Space Complexity: O(1) Stable: Yes

Insertion Sort¶

Builds the final sorted array one item at a time by repeatedly inserting a new element into the sorted portion of the array.

Insertion Sort algorithm implementation.

class algolib.algorithms.sorting.insertion_sort.InsertionSort

Bases: Sorter[ComparableT]

Insertion Sort algorithm - O(n²) time complexity, O(1) space complexity.

Insertion sort is a simple sorting algorithm that builds the final sorted array one element at a time. It works by taking elements from the unsorted portion and inserting them into their correct position in the sorted portion.

Time Complexity:

  • Best Case: O(n) - when the array is already sorted

  • Average Case: O(n²) - random order

  • Worst Case: O(n²) - when the array is sorted in reverse order

Space Complexity: O(1) - constant space usage (in-place sorting)

Characteristics:

  • Stable: Equal elements maintain their relative order

  • In-place: Sorts the array without using extra space

  • Adaptive: Performs better on partially sorted arrays

  • Online: Can sort a list as it receives it

Advantages:

  • Simple implementation

  • Efficient for small datasets

  • Stable sorting algorithm

  • Adaptive (performs well on nearly sorted arrays)

  • Online (can sort data as it’s received)

  • No additional memory space needed

Disadvantages:

  • Poor performance on large datasets

  • More writes compared to selection sort

  • Not as efficient as advanced algorithms for large datasets

Common use cases:

  • Small datasets where simplicity is preferred

  • Nearly sorted arrays (performs very well)

  • As a subroutine in hybrid algorithms (like Timsort)

  • When stability is required and dataset is small

  • Real-time applications where data arrives incrementally

Example

>>> sorter = InsertionSort()
>>> result = sorter.sort([64, 34, 25, 12, 22, 11, 90])
>>> print(result)  # Output: [11, 12, 22, 25, 34, 64, 90]
>>> result = sorter.sort([5, 2, 4, 6, 1, 3])
>>> print(result)  # Output: [1, 2, 3, 4, 5, 6]

Selection Sort¶

Divides the input list into a sorted and unsorted region, and repeatedly selects the smallest element from the unsorted region.

Selection Sort algorithm implementation.

class algolib.algorithms.sorting.selection_sort.SelectionSort

Bases: Sorter[ComparableT]

Selection Sort algorithm - O(n²) time complexity, O(1) space complexity.

Selection sort is a simple sorting algorithm that works by repeatedly finding the minimum element from the unsorted portion of the array and placing it at the beginning of the sorted portion.

Time Complexity:

  • Best Case: O(n²) - even when the array is already sorted

  • Average Case: O(n²) - random order

  • Worst Case: O(n²) - when the array is sorted in reverse order

Space Complexity: O(1) - constant space usage (in-place sorting)

Characteristics:

  • Unstable: Equal elements may not maintain their relative order

  • In-place: Sorts the array without using extra space

  • Not adaptive: Performance doesn’t improve on partially sorted arrays

  • Simple: Easy to understand and implement

Advantages:

  • Simple implementation

  • No additional memory space needed

  • Performs well on small datasets

  • Minimizes the number of swaps (O(n) swaps)

Disadvantages:

  • Poor performance on large datasets

  • Not stable (relative order of equal elements may change)

  • Not adaptive (doesn’t perform better on partially sorted arrays)

  • Always performs O(n²) comparisons

Common use cases:

  • Educational purposes (learning sorting concepts)

  • Small datasets where simplicity is preferred

  • When memory is extremely limited

  • When the cost of swapping is high (minimizes swaps)

Example

>>> sorter = SelectionSort()
>>> result = sorter.sort([64, 25, 12, 22, 11])
>>> print(result)  # Output: [11, 12, 22, 25, 64]
>>> result = sorter.sort([3, 1, 4, 1, 5])
>>> print(result)  # Output: [1, 1, 3, 4, 5]

Graph Algorithms¶

Graph algorithms solve problems involving relationships between objects represented as nodes and edges.

Breadth-First Search (BFS)¶

Explores all vertices at the present depth before moving on to vertices at the next depth level.

Breadth-First Search algorithm for graph traversal.

BFS explores vertices level by level, visiting all neighbors at the current depth before moving to vertices at the next depth level.

Time Complexity: O(V + E) - where V is vertices, E is edges Space Complexity: O(V) - for queue and visited set

Characteristics:

  • Level-by-level: Visits nodes in breadth-first order

  • Queue-based: Uses queue data structure

  • Shortest path: Finds shortest path in unweighted graphs

  • Complete: Explores all reachable vertices

Advantages:

  • Guarantees shortest path in unweighted graphs

  • Memory efficient for sparse graphs

  • Simple to implement and understand

  • Systematic exploration

Disadvantages:

  • Memory intensive for dense graphs

  • Not suitable for very deep graphs

  • Doesn’t work with weighted shortest paths

Example

>>> graph = Graph()
>>> # Add vertices and edges...
>>> bfs = BreadthFirstSearch()
>>> result = bfs.run(graph, start_vertex)

Getting Started¶

To use these algorithms in your code:

from algolib.algorithms.sorting import QuickSort
from algolib.algorithms.searching import BinarySearch
from algolib.algorithms.graph import Dijkstra

# Sort a list
sorter = QuickSort[int]()
data = [64, 34, 25, 12, 22, 11, 90]
sorted_data = sorter.sort(data)

# Search in sorted data
searcher = BinarySearch[int]()
index = searcher.search(sorted_data, 25)

Algorithm Selection Guide¶

  1. For Small Datasets (< 50 elements): Use Insertion Sort or Bubble Sort

  2. For General Purpose Sorting: Use Quick Sort or Merge Sort

  3. For Stable Sorting: Use Merge Sort or Insertion Sort

  4. For Searching in Sorted Data: Use Binary Search

  5. For Graph Traversal: Use BFS for shortest path, DFS for exploration

  6. For Optimization Problems: Consider Greedy algorithms first

Best Practices¶

  1. Understand Trade-offs: Consider time vs space complexity

  2. Choose Appropriate Data Structures: The right structure can make algorithms much more efficient

  3. Test Edge Cases: Always test with empty arrays, single elements, and duplicate values

  4. Profile Performance: Use benchmarking tools to measure actual performance
