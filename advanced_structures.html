Advanced Data Structures¶

This guide covers advanced data structures that provide sophisticated functionality and performance characteristics for complex applications.

Overview¶

Advanced data structures build upon basic concepts to provide specialized functionality, better performance guarantees, and solutions to complex problems.

Self-Balancing Binary Search Trees¶

Self-balancing trees automatically maintain their height to ensure efficient operations regardless of the order of insertions and deletions.

AVL Tree¶

An AVL tree is a self-balancing binary search tree where the heights of the two child subtrees of any node differ by at most one.

AVL Tree (self-balancing BST) implementation.

Space Complexity: O(n)

Key Features: - Strict height balancing - Guaranteed O(log n) performance - More rotations than Red-Black trees

AVL Tree Rotations¶

AVL trees use rotations to maintain balance after insertions and deletions.

Rotation Types: - Left Rotation: Used when the right subtree is taller - Right Rotation: Used when the left subtree is taller - Left-Right Rotation: Double rotation for left-right imbalance - Right-Left Rotation: Double rotation for right-left imbalance

Red-Black Tree¶

A Red-Black tree is a self-balancing binary search tree with additional properties that ensure the tree remains approximately balanced.

Red-Black Tree implementation (insertion only).

Space Complexity: O(n)

Properties: 1. Every node is either red or black 2. The root is always black 3. Red nodes cannot have red children 4. Every path from root to leaves has the same number of black nodes

Red-Black Tree Fix-up Operations¶

Red-Black trees use color changes and rotations to maintain properties after insertions and deletions.

Insertion Fix-up Cases: - Case 1: Uncle is red - recolor parent, uncle, and grandparent - Case 2: Uncle is black, triangle case - rotate parent - Case 3: Uncle is black, line case - rotate grandparent and recolor

Deletion Fix-up Cases: - Case 1: Sibling is red - rotate parent and recolor - Case 2: Sibling and nephews are black - recolor sibling - Case 3: Sibling is black, far nephew is black - rotate sibling - Case 4: Sibling is black, far nephew is red - rotate parent and recolor

Heap Data Structure¶

A heap is a specialized tree-based data structure that satisfies the heap property.

Max Heap implementation for HeapSort and other algorithms.

class algolib.data_structures.heap.MaxHeap(key: Callable[[T], object] | None = None)

Bases: Generic[T]

A max heap implementation supporting custom comparison functions.

This max heap uses a list-based representation where for any node at index i: - Left child is at index 2*i + 1 - Right child is at index 2*i + 2 - Parent is at index (i-1)//2

Trie (Prefix Tree)¶

A trie is a tree-like data structure used to store a dynamic set of strings where the keys are usually strings.

Trie (prefix tree) implementation for efficient string storage & lookup.

Getting Started¶

To use these advanced data structures:

from algolib.data_structures import AVLTree, RedBlackTree, Heap, DisjointSet, Trie

# AVL Tree
avl = AVLTree[int]()
avl.insert(10)
avl.insert(20)
avl.insert(30)

# Red-Black Tree
rb_tree = RedBlackTree[int]()
rb_tree.insert(15)
rb_tree.insert(25)
rb_tree.insert(35)

# Heap (Max Heap)
heap = Heap[int]()
heap.push(10)
heap.push(20)
heap.push(5)
max_value = heap.pop()  # 20

# Disjoint Set
ds = DisjointSet[int]()
ds.make_set(1)
ds.make_set(2)
ds.union(1, 2)

# Trie
trie = Trie()
trie.insert("hello")
trie.insert("world")
contains_hello = trie.search("hello")  # True

Performance Comparison¶

Structure | Search | Insert | Delete | Space |

|-----------|——–|--------|——–|-------| | AVL Tree | O(log n) | O(log n) | O(log n) | O(n) | | Red-Black Tree | O(log n) | O(log n) | O(log n) | O(n) | | Heap | O(n) | O(log n) | O(log n) | O(n) | | Disjoint Set | O(α(n)) | O(α(n)) | - | O(n) | | Trie | O(m) | O(m) | O(m) | O(ALPHABET_SIZE * m * n) |

When to Use Each Structure¶

  1. AVL Tree: When you need guaranteed O(log n) performance and can tolerate more rotations

  2. Red-Black Tree: When you want good average performance with fewer rotations

  3. Heap: For priority queue operations and heap sort

  4. Disjoint Set: For tracking connected components and union-find operations

  5. Trie: For string operations, autocomplete, and prefix matching

  6. Graph: For representing relationships and network structures

Best Practices¶

  1. Choose Based on Operations: Consider which operations you’ll perform most frequently

  2. Understand Trade-offs: Balance between time complexity, space complexity, and implementation complexity

  3. Consider Memory Usage: Advanced structures may use more memory than simpler alternatives

  4. Profile Performance: Test with your specific use case and data patterns
